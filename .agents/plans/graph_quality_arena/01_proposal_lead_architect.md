# Lead Architect Proposal: Graph Compiler After Claim Integrity

Date: 2026-06-11 | Agent Persona: lead_architect

## 1. Core Logic & Implementation

Plan C begins only after Plan B publishes stable claim identities and support
eligibility. It then executes:

```text
eligible claims
  -> reversible entity resolution
  -> independent relation support
  -> filtered active topology
  -> measured hierarchy
  -> claim-grounded reports
```

Every stage is separately auditable and reversible. No serving concern or quota
policy enters this compiler boundary.

## 2. Pros & Cons

Pros: prevents noisy extraction from being hidden by clustering and makes
community changes explainable. Cons: hierarchy work cannot start early and graph
rebuild/migration cost must be measured explicitly.
