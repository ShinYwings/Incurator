# 🧠 Incurator: 멀티 에이전트 워크스페이스를 위한 지식 컴파일러 & 연구 어시스턴트

[English](README.md) | **한국어**

**"PDF와 노트를 로컬 AI 컴파일러에 맡기세요. 내 지식에 기반해 질문하고, Cursor처럼 노트를 편집하며, MCP로 코딩 IDE에 볼트 지식을 연동하세요."**

Incurator는 이미 옵시디언 볼트에 있는 PDF와 노트를 AI가 실제로 쓸 수 있는 지식
그래프로 바꿉니다.

한 번 컴파일해 두고 — 로컬의 작은 모델로, 거의 비용 없이 — 그 그래프에서 질문에
답합니다. 모든 주장에는 근거가 된 원문 구절이 함께 붙습니다. 사용자의 자료로
되짚을 수 없는 것은 말하지 않습니다.

> 시스템의 설계 철학과 기존 LLM Wiki들의 한계를 극복한 아키텍처 배경은 [프로젝트 철학](philosophy/ABOUT_KR.md) 문서를 참조하세요.

## 🚀 사용자가 경험하는 핵심 워크플로우

```
  [볼트 원본 자료] (03_Notes/, 04_Resources/, Zotero PDF)
       │
       ▼ (wiki add / wiki build)
┌──────────────────────────────────────────────────────────────┐
│ 🏛️ The Curator (.curator/ 및 state.sqlite)                   │
│   L1 맥락(Context) → L2 원자(Atoms) → L3 개념 → L4 합성     │
│   (로컬 SLM / 백그라운드 워커가 저비용으로 지식 컴파일)      │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼ (curate.yml 기반의 동적 큐레이션 렌즈)
┌──────────────────────────────────────────────────────────────┐
│ 🎨 The Artist (옵시디언 사이드바 & Universal MCP 서버)       │
│   • 열린 PDF 분할 뷰 연동 & 소스 상태 배지                   │
│   • 텍스트 드래그 인라인 팝오버 질문 ("Ask Gemini" 스타일)   │
│   • Cursor 스타일의 인터랙티브 인라인 Diff 노트 편집         │
│   • 다중 출처 하이브리드 검색 & 정확한 출처 인용 답변         │
│   • 외부 코딩 IDE(Cursor, VSCode)를 위한 실시간 컨텍스트 제공 │
└──────────────────────────────┬───────────────────────────────┘
                               │
            ┌──────────────────┴──────────────────┐
            ▼ (Diff 리뷰를 통한 선별 수정)        ▼ (wiki query "save" / 명시적 승격)
    [03_Notes/] (업데이트된 내 노트)       [02_Wiki/] (영구 위키 지식)
```

1. **등록** (`wiki add`) — `03_Notes/`나 `04_Resources/`에 PDF나 노트를 넣으면
   LLM 호출 없이 구조 인덱스가 즉시 만들어집니다.
2. **컴파일** (`wiki build`) — 작은 로컬 모델이 사실 단위를 뽑아내고 여러 문헌을
   가로지르는 주제로 묶습니다. 느리지만 값싼 부분이 여기입니다.
3. **읽고 묻기** — PDF를 분할 뷰로 열고, 텍스트나 수식을 선택해 그 자리에서
   답을 받거나 사이드바에서 대화합니다. 모든 답변에 인용이 붙습니다.
4. **검토하며 편집** — AI 제안이 노트 안에 diff로 도착합니다. 청크 단위로
   수락하거나 거절하며, 조용히 덮어써지는 일은 없습니다.
5. **범위 지정** (`curate.yml`) — 프로젝트가 무엇에 관심 있는지 선언하면 검색이
   볼트 전체를 훑는 대신 주제 안에 머뭅니다.
6. **다른 도구에서 쓰기** — Cursor나 Claude Desktop을 MCP로 볼트에 연결합니다.

## 🌟 다른 LLM Wiki와 무엇이 다른가

대부분의 LLM Wiki는 문서를 읽고 그에 관한 마크다운 더미를 씁니다. 그리고 그
더미가 곧 문제가 됩니다 — 컨텍스트 윈도우에 다 들어가지 않고, 출처에서 점점
멀어지며, 어느 부분을 믿어도 되는지 아무도 알려주지 않습니다.

Incurator는 요약하는 대신 **컴파일**하고, 사용자의 자료로 되짚을 수 없는 것은
말하지 않습니다.

| | 일반적인 LLM Wiki | Incurator |
|---|---|---|
| **결과물** | 수백 개의 평면 마크다운 파일 | *읽는* 게 아니라 *질의하는* 4계층 그래프 |
| **근거** | 모델이 요약하고, 출처와 점점 멀어짐 | 정확한 source span을 인용할 수 없는 발견은 **아예 생성되지 않음** |
| **내 노트** | AI가 덮어씀 | 기계에게는 읽기 전용. AI 산출물은 별도 공간에 쌓이고, 승격은 사람이 결정 |
| **범위 지정** | 모든 질문에 하나의 전역 인덱스 | `curate.yml`은 *질의 시점에* 적용되는 렌즈 — 얼어붙은 사본이 아님 |
| **비용** | 전부 프런티어 모델로 | 컴파일은 작은 로컬 모델이, 프런티어 모델은 대화형 추론에만 |
| **신뢰** | "답은 이것입니다" | 모든 답변이 route·근거·prompt trace를 함께 보관 (`wiki inspect answer`) |

4개 계층은 **검색 범위를 좁히기 위해** 존재합니다: **L1** 소스 구조(LLM 토큰 0),
**L2** 더 쪼갤 수 없는 사실 단위, **L3** 여러 소스를 가로지르는 주제, **L4**
코퍼스 전체의 종합. 질문은 볼트 전체가 아니라 필요한 계층만 건드립니다.

## 🧰 실제로 제공되는 것

- **Obsidian 스튜디오** — PDF 분할 뷰와 수집 상태 배지, 선택한 텍스트나 수식에
  바로 뜨는 인라인 팝오버, 그리고 AI 편집을 통째로 덮어쓰는 대신 청크 단위로
  수락/거절하는 CodeMirror diff 뷰어.
- **복제 없는 Zotero 연동** — 외부 라이브러리를 제자리에서 참조합니다. iPad에서
  PDF에 필기하면 바이너리 해시가 바뀌지만, 논리적 신원과 텍스트 지문을 추적해
  기존 Atom과 Concept이 살아남습니다.
- **48개 도구를 갖춘 MCP 서버** — Cursor, VS Code, Antigravity, Claude Desktop을
  볼트에 연결해 코딩 에이전트가 내 논문과 RFC를 직접 가져오게 합니다.
- **모순 탐지** — `wiki lint --deep`이 서로 다른 논문에서 어긋나는 주장을 찾습니다.
- **다중 기기 동기화** — SQLite WAL 체크포인트, 상대 경로, 자동 생성되는
  `.stignore` 규칙으로 macOS·Linux·iPad 간 충돌 없는 Syncthing/iCloud 사용.

## 🏛️ 시스템 아키텍처: Curator & Artist

Incurator는 지식 관리의 역할을 두 주체로 엄격히 분리합니다.

### ⚙️ The Curator (볼트의 관리자)
`.curator/`에 상주하는 백그라운드 엔진입니다. 고도의 창의적 추론 대신 **지식의 구조화, 컴파일, 인덱싱 및 무결성 감사**를 전담합니다.
- `state.sqlite`가 단일 진실 공급원이며, `.curator/Collections/`의 마크다운 파일들은 언제든 삭제하고 다시 빌드할 수 있는 점검용 프로젝션입니다.

### 🎨 The Artist (워크스페이스의 창작자: 인간 + 에이전트)
옵시디언 사이드바나 MCP를 통해 사용자와 협업하는 고성능 추론 주체입니다.
- **동적 큐레이션 렌즈**: 고정된 하위 복사본을 만드는 대신, `curate.yml` 명세를 쿼리 시점에 라이브 DAG 위에 렌즈 형태로 동적 적용합니다.
- **무상태(Sessionless) 질의**: 질문을 던지는 행위 자체는 DAG를 오염시키지 않습니다. 모든 질의는 출처 인용 및 추적 정보가 포함된 답변을 반환합니다.
- **명시적 승격(Promotion)**: 가치 있는 결과물은 인간의 명시적 승인을 거쳐야만 `02_Wiki/`의 영구 지식으로 보존됩니다.

## 🛠️ 시작하기

### 📋 사전 요구 사항
- **Python 3.10+**
- **옵시디언 (Obsidian)** (인터랙티브 UI 권장)
- **로컬 / 클라우드 LLM**: 로컬 모델(Ollama) 또는 클라우드 API 키(Claude, OpenAI, Gemini 등).

### 🚀 빠른 시작 (Quick Start)
1. **설치 및 모노레포 빌드**:
   ```bash
   ./setup.sh
   ```
   *파이썬 의존성 설치, 옵시디언 플러그인 빌드 및 로컬 도구 설정을 한 번에 진행합니다.*

2. **볼트 초기화**:
   ```bash
   wiki init /path/to/your/obsidian-vault
   ```
   *간단한 인터뷰를 통해 볼트의 Curator 페르소나를 설정합니다.*

3. **자료 등록**:
   ```bash
   wiki add /path/to/document.pdf
   ```
   *LLM 비용 없이 L1 문서 구조를 즉각 생성합니다.*

4. **지식 레이어 컴파일**:
   ```bash
   wiki build
   ```
   *백그라운드에서 L2 원자 및 L3 개념을 추출·클러스터링합니다.*

5. **질의 및 지식 탐색**:
   ```bash
   wiki query "등록된 논문들에서 발견된 핵심 결과는 무엇인가요?"
   ```
   *또는 옵시디언을 열어 사이드바 및 인라인 팝오버로 노트와 PDF를 실시간 탐색합니다.*
