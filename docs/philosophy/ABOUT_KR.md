# 💡 Incurator는 왜 만들어졌는가

## 지식 시스템의 진화: 단순 RAG에서 LLM Wiki로

논문, PDF, 연구 노트와 같은 방대한 문서를 다룰 때, 키워드 검색이나 단순 RAG(Retrieval-Augmented Generation)는 한계에 부딪힙니다. 단순 RAG는 문서를 기계적인 텍스트 덩어리(청크)로 쪼개어 매번 무작위 검색할 뿐, 여러 문헌을 관통하는 상위 개념과 맥락을 이해하지 못합니다.

이를 해결하기 위해 등장한 개념이 바로 **"LLM Wiki"** 패턴입니다. 매 질의마다 원본 텍스트를 헤집는 대신, AI 에이전트가 문서를 읽고 정제하여 상호 연결된 지속적인 마크다운 위키로 사전 컴파일하는 방식입니다.

그러나 현재 GitHub 등에 공개된 기존의 오픈소스 LLM Wiki 구현체들은 세 가지 치명적인 구조적 결함을 안고 있습니다.

---

## 기존 LLM Wiki의 3대 한계와 함정

### 1. 진실의 왜곡과 환각 누적 (The Silent Overwrite Trap)
대부분의 LLM Wiki는 AI가 기존 마크다운 노트를 직접 수정하고 덮어쓰는 구조를 가집니다. 만약 LLM이 문서를 파싱하면서 사소한 환각이나 왜곡을 일으키면, 그 오류가 영구적인 위키 텍스트로 굳어집니다. 이후의 AI 작업들은 과거의 왜곡된 위키 텍스트를 "원본 진실(Ground Truth)"로 간주하여 인용하므로, 시간이 지날수록 원본과의 연결이 끊어지고 시스템 전체에 환각이 누적(Truth Decay)됩니다.

### 2. 컨텍스트 윈도우 폭발과 평면적 확장 (The Scalability Trap)
위키 페이지가 150~200개를 넘어가기 시작하면, AI 에이전트는 위키 전체 구조를 컨텍스트에 담지 못합니다. 이로 인해 중복 페이지를 생성하고, 연결해야 할 교차 링크를 놓치며, 엉뚱한 관계를 날조합니다. 단순한 평면 위키링크(`[[개념]]`)만으로는 A 논문이 B 이론을 **'지지'**하는지, **'반박'**하는지, **'개선'**하는지 구별할 수 없습니다.

### 3. 컴파일 비용의 폭발 (The FinOps Trap)
방대한 문서를 파싱하고 요약하며 원자 단위 사실을 추출하고 링크를 거는 전 과정에 상용 고성능 추론 모델을 투입하면 막대한 API 비용이 발생합니다. 단순한 텍스트 데이터 전처리와 분해 작업에 비싼 추론 모델을 사용하는 것은 극도의 비효율입니다.

## Incurator의 해결책: 아키텍처와 핵심 원칙

Incurator는 이러한 한계를 극복하기 위해 엄격한 역할 분리와 지식 계층화를 바탕으로 설계되었습니다.

```
  [볼트 원본 자료] (03_Notes/, 04_Resources/, Zotero PDF) ── (보호되는 인간 원본 진실)
       │
       ▼ (wiki add: 즉시 L1 파싱 / wiki build: 로컬 SLM 컴파일)
┌──────────────────────────────────────────────────────────────┐
│ 🏛️ The Curator (.curator/ 및 state.sqlite)                   │
│   L1 맥락(Context) → L2 원자(Atoms) → L3 개념 → L4 합성     │
│   (언제든 재생성 가능한 기계 판독용 지식 DAG)                │
└──────────────────────────────┬───────────────────────────────┘
                               │
                               ▼ (curate.yml 기반의 동적 큐레이션 렌즈)
┌──────────────────────────────────────────────────────────────┐
│ 🎨 The Artist (옵시디언 사이드바 & Universal MCP 서버)       │
│   • 텍스트 드래그 인라인 팝오버 질문 & PDF 분할 뷰 연동      │
│   • Cursor 스타일의 인터랙티브 마크다운 Diff 리뷰 및 패치     │
│   • 다중 문헌 간 심층 모순(Contradiction) 탐지 및 합성      │
│   • 외부 코딩 IDE(Cursor / VSCode)를 위한 MCP 브레인 연동     │
└──────────────────────────────┬───────────────────────────────┘
                               │
            ┌──────────────────┴──────────────────┐
            ▼ (Diff 리뷰를 통한 선별 수정)        ▼ (인간 검토 후 명시적 승격)
    [03_Notes/] (업데이트된 내 노트)       [02_Wiki/] (영구 위키 지식)
```

### 1. 이원화 공간 분리: AI 작업실 vs 영구 보호 인간 볼트
- **AI 공간 (`.curator/`)**: SQLite 기반의 기계 판독용 지식 그래프이자 점검용 프로젝션입니다. 볼트 원본 문서만 있으면 언제든 통째로 삭제하고 다시 빌드할 수 있는 독립적 재생성 영역입니다.
- **인간 볼트 공간 (`03_Notes/`, `04_Resources/`, `02_Wiki/`)**: 사용자의 고유 영역입니다. 사용자가 직접 쓴 일상 노트와 연구 메모(`03_Notes/`), 논문/PDF 자료(`04_Resources/`), 검증된 영구 지식(`02_Wiki/`)은 모두 완벽히 보호되는 원본 진실입니다. AI는 사용자의 노트를 무단으로 덮어쓰지 않으며, 노트 수정 제안은 인터랙티브 Diff Viewer를 통해 사용자가 확인 후 적용하고, 새로운 상위 지식은 명시적 검토를 거쳐 `02_Wiki/`로 승격됩니다.

### 2. 4단계 계층형 DAG (평면적 위키링크의 한계 극복)
수백 개의 평면 페이지 대신 정형화된 지식 계층을 형성합니다:
- **L1 Contexts**: 원본 문서 구조 파악, 섹션/페이지 위치 및 출처 추적.
- **L2 Atoms**: 원본에 기반한 분해 불가능한 사실 단위.
- **L3 Concepts**: 다중 문헌을 횡단하는 주제별 개념 클러스터 및 리포트.
- **L4 Synthesis**: 말뭉치 전체를 아우르는 공유 상위 지식 노드.

### 3. AI FinOps: 컴파일과 추론의 완벽한 분리
- **지식 컴파일**: 단순 구조화와 사실 원자화(`L1 → L2 → L3`)는 로컬 SLM(Ollama 등)이나 경량 백그라운드 워커가 0원에 가깝게 자동 처리합니다.
- **지식 추론**: 질문 답변, 심층 합성, 가설 검증 등 높은 지능이 필요한 순간에만 상용 고성능 모델과 인간이 협업합니다.

### 4. 연구자를 위한 액티브 리딩 스튜디오 & Universal MCP
지식이 터미널 CLI 안에 갇히지 않습니다:
- **Obsidian Studio**: 열린 PDF 분할 뷰, 텍스트 드래그 즉시 질문(In-line Popover), 그리고 마크다운 노트를 안전하게 편집할 수 있는 Cursor 스타일의 인라인 Diff Review를 제공합니다.
- **Universal MCP Server**: 볼트의 지식 그래프를 Cursor, VSCode, Claude Desktop 등 외부 개발 환경에 실시간 제공하여, 코딩이나 집필 시 내 지식 베이스를 전속 AI 어시스턴트로 활용할 수 있습니다.

지식은 한 번 보고 잊히는 아카이브가 아니라, 스스로 오류를 바로잡고 끊임없이 성장하는(Increment) 유기체가 됩니다.
