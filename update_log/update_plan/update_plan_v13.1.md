## 2. Module-by-Module Changes

### A. New: `curate_yml.py` — curate.yml Parser

New module: `src/llm_wiki/curate_yml.py`

Responsibilities:
- Load and validate a `curate.yml` file from a workspace path
- Return a typed `CurateSpec` dataclass
- Search `01_Workspaces/` for all workspaces with `curate.yml` (for `wiki workspace list`)

```python
# curate_yml.py interface (to implement)

@dataclass
class CurateSpec:
    project: str
    description: str = ""
    domains: list[str] = field(default_factory=list)
    topics: list[str] = field(default_factory=list)
    min_confidence: float = 0.60
    scope: str = "all"

def load_curate_spec(workspace_path: Path) -> CurateSpec | None:
    """Load curate.yml from workspace_path. Returns None if file absent."""

def find_workspaces(vault_root: Path) -> list[tuple[Path, CurateSpec]]:
    """Return all (workspace_path, spec) pairs under 01_Workspaces/."""
```

Validation rules (raise ValueError on failure):
- `min_confidence` must be in [0.0, 1.0]
- `scope` must be one of: all | contexts | atoms | concepts | exhibitions
- `project` must be non-empty

### B. `config.py` — Workspace Path Support

Add helper:
```python
def find_workspace_curate_yml(vault_root: Path) -> Path | None:
    """Check WORKSPACE_PATH env var, then scan 01_Workspaces/ for active curate.yml."""
```

No changes to `WikiPaths`, `COLLECTION_LAYERS`, or any v13.0 changes.

### C. `mcp_server.py` — curate.yml-Scoped search_curator

In `search_curator`:
1. Read `WORKSPACE_PATH` environment variable.
2. If set, call `curate_yml.load_curate_spec(Path(workspace_path))`.
3. If spec loaded:
   - Override `scope` with `spec.scope` (unless caller explicitly set scope ≠ "all")
   - Apply `min_score = max(min_score, spec.min_confidence)` as a floor
   - Append domain/topic terms to the query for relevance boosting:
     `boosted_query = f"{query} {' '.join(spec.topics + spec.domains)}"`
4. Pass boosted query and filters to `search.query(...)`.

No changes to any other MCP tools.

### D. `cli.py` — New Commands and --workspace Flag

**1. `wiki curate --workspace PATH`** (addition to existing `curate` command):
```python
@app.command("curate")
def cmd_curate(
    ...
    workspace: Optional[Path] = typer.Option(None, "--workspace", help="Path to workspace with curate.yml"),
):
    spec = None
    if workspace:
        from .curate_yml import load_curate_spec
        spec = load_curate_spec(workspace)
        if spec is None:
            console.print(f"[yellow]Warning: no curate.yml found in {workspace}[/yellow]")
    # Pass spec into ingest_llm pipeline for Pass 3 prioritization
```

**2. `wiki workspace` subcommand** (new):
```python
workspace_app = typer.Typer(name="workspace", help="Manage workspace curate.yml specs.")
app.add_typer(workspace_app)

@workspace_app.command("init")
def workspace_init(path: Path):
    """Scaffold workspace directory with curate.yml template."""

@workspace_app.command("list")
def workspace_list():
    """List all workspaces with curate.yml under 01_Workspaces/."""
```

### E. `ingest_llm.py` — Pass 3 curate.yml Scope (Optional Enhancement)

If a `CurateSpec` is passed into `_run_pass3_synthesis`:
- Filter or boost concept clusters whose `domain` matches `spec.domains`
- This is a soft prioritization, not a hard filter (all concepts still processed)

This is an optional enhancement for v13.1. If deferred, the `--workspace` flag reads curate.yml but only affects MCP search, not Pass 3 internally.
